# Критерии ревью календаря бронирований

## Основные правила

### 1. Занятый слот не должен оставаться доступным

При успешном бронировании слота он помечается как занятый и исчезает из списка доступных слотов для других пользователей.

**Проверка:** после создания бронирования повторный запрос на тот же слот должен возвращать ошибку.

**Замечание должно содержать:** файл, строку, условия ошибки (например, `409 Conflict`), последствие (пользователь может забронировать уже занятый слот → дублирование встреч).

### 2. Повторное бронирование отклоняется

Попытка забронировать уже занятый слот должна завершаться с ошибкой `409 Conflict` и понятным сообщением о пересечении.

**Проверка:** отправить запрос на занятый слот → ожидается `409 Conflict`.

**Замечание должно содержать:** файл, строку, условия ошибки, последствие (пользователь видит ошибку, но если код не проверяет пересечения — возникает дублирование).

### 3. Соседний сценарий: бронирование без заметки

Система должна корректно обрабатывать бронирования как с заметкой, так и без неё. Отсутствие заметки не должно ломать бронирование.

**Проверка:** создать бронирование без заметки → слот становится занятым, запись появляется в списке предстоящих встреч.

**Замечание должно содержать:** файл, строку, условия ошибки, последствие.

### 4. Конфликт бронирований

Два бронирования не могут пересекаться по времени для одного пользователя.

**Проверка:** попытка создать бронирование, пересекающееся по времени с существующим, должна быть отклонена.

**Замечание должно содержать:** файл, строку, условия ошибки, последствие.

---

## Формат замечания

Каждое замечание авторевью должно содержать:

- **Файл:** путь к файлу в репозитории
- **Строка:** номер строки (или диапазон)
- **Условия ошибки:** что должно произойти
- **Последствие:** влияние на пользователя или систему

Если подтверждённых дефектов нет — явно сообщить об этом: «Подтверждённых дефектов не обнаружено».
